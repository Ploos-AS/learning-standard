# M0.12 — Pre-tag smoke adoption

This smoke test validates that PLS 0.1 can be adopted by materially different educational repositories before the first `v0.1.0` tag is created.

## Repositories

### EduCPU

- profile: CPU architecture, software toolchain, emulator and FPGA/hardware realization
- declared range: PLS-0 -> PLS-4
- status: `adopting`
- languages: Norwegian and English
- validation: PASS

### EduPython-Kids

- profile: beginner programming for children around 9–12 years old
- declared range: PLS-0 -> PLS-2
- status: `adopting`
- languages: Norwegian and English
- validation: PASS

### Edu65xx

- profile: assembly-first computer architecture course with C, simulator/emulator and physical hardware
- declared range: PLS-0 -> PLS-3
- status: `adopting`
- languages: Norwegian and English
- validation: PASS

## Findings

No PLS schema change or project-specific exception was required.

One YAML interoperability issue was discovered during the smoke test: an unquoted language code `no` is parsed by PyYAML as boolean `false`. PLS examples and adopters MUST therefore quote language codes that can be interpreted as YAML booleans, for example:

```yaml
language:
  - "no"
  - "en"
```

The downstream workflow template was also hardened before release:

- PLS reference changed from development branch `main` to release tag `v0.1.0`;
- Python pinned to 3.12;
- `PyYAML==6.0.2` and `jsonschema==4.23.0` pinned for reproducibility.

## Result

The pre-tag smoke gate passes. PLS 0.1 has now been exercised against:

1. a mathematics/computer-number-systems book/course (`EduNumbers`);
2. a CPU/FPGA/system architecture course (`EduCPU`);
3. an age-targeted beginner programming course (`EduPython-Kids`);
4. a real-CPU assembly/C/hardware course (`Edu65xx`).

No structural blocker to `v0.1.0` was found.
